## Stuff I Learned Today (Angelo)

### 1. App shell vs page content
- index.html is the static shell with `<div id="root"></div>`
- main.jsx boots React and renders `<App />`
- App.jsx is the global layout:
  - header
  - main content area
  - footer
- child pages like `CareerCatalogPage` live inside App.jsx

### 2. Where to put a component
- If a component is only used inside one page:
  - define it in that page file
  - keep it local
- If a component is reused across pages:
  - put it in a shared file
  - import it where needed

### 3. Example
- `LogoButton` used in many headers → reusable shared component
- `CatalogButton` only used in `CareerCatalogPage` → local page component

### 4. Why this matters
- App.jsx composes the page structure
- child components provide page-specific content
- a broken child component can stop the whole render tree
- so keep shared layout in App.jsx and feature UI inside the page/module

### 5. Simple rule
- global layout → App.jsx
- page-specific UI → page file
- reusable UI → shared component file

### 6. HTML containers: `div`, `section`, and React `Fragment`

These elements are all "containers" but they serve very different purposes for accessibility, SEO, and structural organization.

- **`div` (The Generic Box):**
  - When to use: for pure styling or layout where no other semantic tag fits (flex/grid wrappers).
  - Impact: screen readers and search engines treat it as neutral; it adds no semantic meaning.

- **`section` (The Semantic Container):**
  - When to use: for thematic groupings of content that belong in the document outline (example: Career Catalog area).
  - Impact: improves accessibility and SEO because assistive tech and search engines can identify and navigate sections.

- **`<>` (React Fragment):**
  - When to use: to return multiple elements from a React component without adding an extra DOM node.
  - Impact: keeps the DOM tree cleaner by avoiding unnecessary wrappers.

**Quick guidance:**

- Use `section` for distinct page blocks like catalog pages or article sections.
- Use `div` for low-level layout or when no semantic tag applies.
- Use React fragments when you need grouping inside components without adding markup.

Pro-tip: prefer semantic HTML (`header`, `main`, `section`, `article`, `nav`, `footer`) whenever it makes sense — it makes your markup more accessible and self-documenting.
